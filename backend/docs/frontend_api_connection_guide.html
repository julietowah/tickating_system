1. The big picture

The frontend and backend are two separate programs. They may run on the same computer during development, but they listen on different ports.

StudentClicks a button or submits a form
→
JavaScriptBuilds an HTTP request with fetch()
→
FastAPIValidates, authenticates, and queries SQLite
→
JSON responseJavaScript updates the HTML page

Frontend

Address: http://127.0.0.1:5500

Displays forms, buttons, tables, messages, and ticket details.

Backend API

Address: http://127.0.0.1:8000

Receives requests and returns JSON data and HTTP status codes.

Do not open index.html by double-clicking it Serve the frontend through a local HTTP server. This gives it a normal origin and makes browser/API behaviour easier to understand and debug.

4. Know the API contract

An API contract tells the frontend which URL, method, data, authentication, and response format to use.

MethodEndpointPurposeJWT required?
POST/auth/registerCreate a normal userNo
POST/auth/loginReceive an access tokenNo
GET/users/meLoad the signed-in user's profileYes
POST/ticketsCreate a ticketYes
GET/ticketsList, filter, and paginate ticketsYes
GET/tickets/{ticket_id}Retrieve one visible ticketYes

For example, registration expects this JSON body:

{
  "full_name": "Ada Okafor",
  "email": "ada@example.com",
  "password": "SecurePass123!"
}

Login returns:

{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer"
}

5. Allow the frontend through CORS

CORS means Cross-Origin Resource Sharing. The browser considers ports 5500 and 8000 to be different origins. Without permission from the backend, the browser blocks frontend requests.

In backend/app/main.py:

from fastapi.middleware.cors import CORSMiddleware

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:5500",
        "http://127.0.0.1:5500",
        "http://localhost:8080",
        "http://127.0.0.1:8080",
    ],
    allow_credentials=False,
    allow_methods=["*"],
    allow_headers=["*"],
)
SettingMeaning
allow_originsOnly these frontend addresses may call the API from a browser.
allow_methods=["*"]Allow GET, POST, PATCH, DELETE, OPTIONS, and other HTTP methods.
allow_headers=["*"]Allow headers such as Content-Type and Authorization.
allow_credentials=FalseThis app uses a bearer header, not browser cookies.
CORS is enforced by browsers Postman or curl may work even when the browser reports a CORS error. Always test the real frontend in a browser.

7. Create one reusable API helper

Instead of repeating fetch(), headers, token handling, JSON parsing, and errors in every function, the frontend uses one helper called apiFetch.

7.1 Store the backend address

const API_BASE_URL = "http://127.0.0.1:8000";

A request to /auth/login becomes http://127.0.0.1:8000/auth/login.

7.2 Build the headers

const headers = new Headers(options.headers || {});

if (options.body && !headers.has("Content-Type")) {
  headers.set("Content-Type", "application/json");
}

if (state.token) {
  headers.set("Authorization", `Bearer ${state.token}`);
}
  • Content-Type: application/json tells FastAPI that the body contains JSON.
  • Authorization: Bearer ... proves which user is making a protected request.
  • The token header is added automatically whenever a token exists.

7.3 Send the request

response = await fetch(`${API_BASE_URL}${path}`, {
  ...options,
  headers,
});

await pauses this async function until the server answers. It does not freeze the whole browser.

7.4 Read JSON and check the result

const payload = contentType.includes("application/json")
  ? await response.json()
  : null;

if (!response.ok) {
  throw new ApiError(getApiMessage(payload, response.status), response.status);
}

return payload;
fetch does not reject every failed HTTP request A 401, 404, or 422 still produces a Response object. That is why the code must check response.ok.

8. Connect registration

1

Stop the browser's default form submission

event.preventDefault();

Without this, the browser reloads the page and JavaScript loses control of the request.

2

Read input values

const formData = new FormData(form);

const registration = {
  full_name: formData.get("full_name").trim(),
  email: formData.get("email").trim(),
  password: formData.get("password"),
};

The names must match both the HTML input names and the FastAPI schema fields.

3

Send POST /auth/register

await apiFetch("/auth/register", {
  method: "POST",
  body: JSON.stringify(registration),
});

JSON.stringify() converts a JavaScript object into JSON text for the request body.

4

Update the screen

form.reset();
elements.loginEmail.value = registration.email;
switchAuthTab("login");
showToast("Account created. You can sign in now.");

The frontend does not automatically log in because the registration endpoint returns a user, not a token.

9. Connect login and save the JWT

9.1 Send the credentials

const response = await apiFetch("/auth/login", {
  method: "POST",
  body: JSON.stringify({
    email: formData.get("email").trim(),
    password: formData.get("password"),
  }),
});

9.2 Save the returned token

state.token = response.access_token;
localStorage.setItem("deskflow_access_token", state.token);

state.token

Keeps the token available while the current page is open.

localStorage

Keeps the token after a refresh or browser restart.

Teaching note about token storage localStorage is simple for this learning project, but production applications must carefully protect against cross-site scripting. Secure cookie-based designs are also common.

9.3 Load the signed-in user

state.user = await apiFetch("/users/me");

The API helper automatically adds:

Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

FastAPI decodes the JWT, reads the user ID, loads that user from the database, and returns the safe profile.

9.4 Logout

state.token = null;
state.user = null;
localStorage.removeItem("deskflow_access_token");

JWT logout on this frontend means deleting the locally stored token. After that, protected requests no longer contain an Authorization header.

10. List, filter, and paginate tickets

10.1 Build query parameters safely

const query = new URLSearchParams({
  page: String(state.page),
  page_size: String(state.pageSize),
});

if (state.status) query.set("status", state.status);
if (state.priority) query.set("priority", state.priority);

If the user selects open and high priority, the request URL becomes:

GET /tickets?page=1&page_size=8&status=open&priority=high

10.2 Request the page

const ticketPage = await apiFetch(`/tickets?${query}`);

The backend returns:

{
  "items": [
    {
      "id": 4,
      "title": "Cannot access student portal",
      "priority": "high",
      "status": "open",
      "owner_id": 1,
      "created_at": "2026-10-26T09:10:00"
    }
  ],
  "page": 1,
  "page_size": 8,
  "total": 1
}

10.3 Render tickets into the table

elements.ticketTableBody.innerHTML = items
  .map(ticketRowTemplate)
  .join("");

map() turns every ticket object into an HTML row. join("") combines those rows into one string.

10.4 Calculate pages

const totalPages = Math.max(1, Math.ceil(total / pageSize));

If there are 21 tickets and each page shows 8:

Math.ceil(21 / 8) === 3

The Previous and Next buttons change state.page and call loadDashboard() again.

11. Create a ticket

The create-ticket form collects title, description, and priority. It deliberately does not send owner_id or status.

const ticket = await apiFetch("/tickets", {
  method: "POST",
  body: JSON.stringify({
    title: formData.get("title").trim(),
    description: formData.get("description").trim(),
    priority: formData.get("priority"),
  }),
});
Why this is secure FastAPI obtains the owner from the JWT and automatically starts the ticket as open. A user cannot pretend to be another owner or submit a fake resolved ticket.

After success, the frontend:

  1. Clears the form.
  2. Closes the dialog.
  3. Returns to page 1.
  4. Reloads the dashboard.
  5. Shows the new ticket number.

12. Retrieve one ticket

Each table row has a button containing the ticket ID:

<button data-ticket-id="4">Open</button>

JavaScript reads that value and requests:

const ticket = await apiFetch(`/tickets/${ticketId}`);

It then safely places data into the detail dialog:

elements.detailTitle.textContent = ticket.title;
elements.detailDescription.textContent = ticket.description;
elements.detailOwner.textContent = `#${ticket.owner_id}`;
Prefer textContent for user data textContent displays text without interpreting it as HTML. This helps prevent script injection. The ticket table uses an escaping helper before inserting strings with innerHTML.

13. Error handling

Possible API errors include:

StatusMeaningFrontend response
401Missing, expired, or invalid tokenRemove token and return to login
404Ticket missing or hiddenShow “Ticket not found”
409Email already registeredShow duplicate-account message
422Input failed validationShow field validation messages
0Browser could not reach APITell user to start/check FastAPI

The helper extracts FastAPI validation errors:

if (Array.isArray(payload?.detail)) {
  return payload.detail
    .map((issue) => `${issue.loc?.at(-1)}: ${issue.msg}`)
    .join(". ");
}

Functions use try / catch / finally:

try {
  const response = await apiFetch(...);
  // handle success
} catch (error) {
  showToast(error.message, "error");
} finally {
  setButtonBusy(submitButton, false);
}
  • try: code that may fail.
  • catch: show a helpful error.
  • finally: restore the button whether the request succeeds or fails.

15. Common problems

“Could not reach the API”

  • Confirm Uvicorn is still running.
  • Open http://127.0.0.1:8000/docs.
  • Confirm API_BASE_URL uses port 8000.

CORS error in the browser console

  • Serve the frontend on port 5500 or 8080.
  • Make sure the exact frontend origin is in allow_origins.
  • Restart Uvicorn after changing CORS settings.

401 Unauthorized

  • Log in again and inspect localStorage.
  • Check for Authorization: Bearer ... in Network → Headers.
  • Confirm the backend secret key did not change after issuing the token.

422 Unprocessable Entity

  • Compare JSON keys with the Pydantic schema.
  • Check title and description minimum lengths.
  • Use only low, medium, or high priority.

16. Full connection checklist

  • FastAPI starts on port 8000.
  • The frontend starts on port 5500.
  • CORS includes the frontend origin.
  • The JavaScript API base URL points to port 8000.
  • HTML input names match Pydantic field names.
  • POST requests use JSON.stringify().
  • JSON requests include Content-Type: application/json.
  • Login stores the returned access token.
  • Protected requests include the bearer token.
  • Responses are checked with response.ok.
  • Errors are caught and displayed to the user.
  • Ticket data is rendered safely into the page.
  • Logout removes the stored token.

18. Student exercises

  1. Use the Network tab to find the login request and identify its method, URL, request JSON, status, and response JSON.
  2. Remove the saved token in Application → Local Storage. Refresh the page and explain what happens.
  3. Change pageSize from 8 to 3 and observe pagination.
  4. Submit a ticket title shorter than five characters and study the validation result.
  5. Temporarily change the API port to 9999. Explain the displayed error, then restore port 8000.
  6. Add a “high priority” count by calling /tickets?page=1&page_size=1&priority=high.
  7. When the backend edit endpoint is ready, design a PATCH request using the same apiFetch helper.
